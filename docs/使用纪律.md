## 5. 使用纪律

**铁律一：装机前先审「它运行时会不会动 active 工具集」。** 只要扩展在会话中途调 `pi.setActiveTools`，工具集一变，请求前缀从第 0 个 token 起整段作废——本机实测 `cacheRead` 从 86016 掉到 1152，等于每次首次激活都吃一发全量 prefill（CHANGELOG [§7.4](../CHANGELOG.md)）。所以只接受两种接入方式：① 常驻进 `defaultTools`（前缀恒定）；② 懒加载由 `omnify` 代理执行（只在 `session_start` 隐藏一次，全程不切 active 集）。

- **凡「运行时增删工具」的扩展一律不装、不启用、不写进 `defaultTools`**——哪怕它的工具本身很有用（要联网搜就用 `bash` 自己 curl，别为它掀缓存）。
- 审法：`read` 扩展源码搜 `setActiveTools` / `activeTools`；装完对比首请求的工具字节（口径见 [§6](token优化.md)），不一致就是它在散缓存。

**铁律二：所有命令都带超时。** pi 内建 `bash` 工具的 `timeout` 参数是**可选且无默认值**，不传就是永远跑。本机**没有**守卫扩展（原来的 `pi-bash-guard` 已删），所以靠习惯：

| 命令类型 | 自己传 `timeout` | 备注 |
|---|---|---|
| 搜索（`find` `grep` `rg` `fd`） | `30`–`60` | 大目录先 `-maxdepth` / `-prune` / `-xdev`，别裸跑整盘 |
| 构建 / 装依赖（`npm` `cargo` `docker build`…） | `1800`–`3600` | 给大不亏 |
| 其余 | `300` | 兜底 |
| 编辑器 / 分页器 / REPL / 前台服务（`vim` `less` `tail -f` `ssh` `python` 裸跑 `npm run dev`） | **别跑** | 它们永不返回，给 timeout 只是白等一个上限 |

- 超时后 pi 会 `killProcessTree` 整棵子进程树（Windows `taskkill /F /T`，POSIX `kill(-pid, SIGKILL)`）。
- **唯一会逃掉 kill 的写法**：`cmd &` / `nohup` / `setsid`——shell 立即返回，pi 清掉计时器，命令在工具返回后继续跑、没人再管。所以**别把搜索/构建后台化**。
- `powershell` 工具**没有 `timeout` 参数**，注入不了，里面的 `find` 是 Git 的 GNU find——**别在里面裸跑 `find .`**。

**`find` / `grep` 怎么处理**：由 `@piotr-oles/pi-reflag` 在 `tool_call` 上**透明改写**成 `fd` / `rg`（[§3.7](配置.md)），不拒答、不 block。改不了的 `find` flag 原样保留让 find 自己报错。纪律上仍**优先直接写 `fd` / `rg`**——改写只是兜底。

> 原先的守卫（三档超时注入、无 path 的 `find` 直接 block、`find/grep` 转译表）已随 `pi-bash-guard` / `no-find.ts` 删除，细节见 CHANGELOG [§12](../CHANGELOG.md)。

**0. 新装扩展一律不进常驻集**（硬规则）
   - 理由：常驻集每轮都进 prompt（`grep`+`find` 就要 +1350B ≈ 350 tok），而多数扩展一天用不到几次。
   - **只有这三类才加常驻**：① 高频工具（见 [§6.3](token优化.md) 的取舍）；② 覆盖内建工具的（`grep`/`find`/`edit` 需先过 `defaultTools` 闸）；③ 缺失后 agent 会“瘫”的（如 `bash`）。
   - 例外（唯一）：**`codemode`**。它是 pi 内建扩展且 `defaultActive:false`，**必须进 `defaultTools` 才激活**；又因合成 `builtin:` 源码无法被 `omnify` 代理（`nonLoadableSourceReason`），不常驻就没有任何取用入口。故按第三类「缺失即瘫」对待，破例常驻（[§6.4](token优化.md)）。
   - 其余：无。`grep` 也只是「需要时 `omnify` 激活」，不进名单（[§6.3](token优化.md)）。
1. **首字成本**：常驻集每轮都进 prompt；不在名单的工具靠 `omnify` 检索命中后**代理执行**（不把 schema 注入 active 集，见铁律一）。
2. **激活往返**：`omnify` → 执行，多 1–2 个模型轮次。搜索类工具建议常驻（见 [§6.3](token优化.md)）。
3. **大输出**（`bash` 直接抓页面 / 原始 HTML/JSON）全量进历史，会把前缀命中率打崩；用前先想清楚要不要落历史。
4. **改 `.md` 优先用 `edit` 精确替换**（[§3.6](配置.md)），改动尽量带足上下文行以锚定位置。
6. **纯 UI 类扩展可以放心装**：`pi-tps` / `pi-one-ui` / `pi-dsh-pet` / `pi-pet-autostart` 这类只挂事件钩子、只注册命令的扩展，**不注册任何工具**，不进 `defaultTools`，wire 字节不变（[§3.3](配置.md) 有 bench 实测：装宠物前后都是 5664B）。反过来，任何**注册工具**的扩展都要重新算 [§6.3](token优化.md) 那笔账。

**全局规则：本机不发任何提示词层规则**（定案，不恢复）

`~/.pi/agent/AGENTS.md` 与仓库 `config/agent/AGENTS.md` **都是 0B**。命令怎么写、文件怎么读，交给模型自己按当下的报错与上下文判断，不靠一段常驻 system 前缀去求它照做。

| 曾经的规则块 | 现在的替代 |
|---|---|
| Think: minimal sufficient reasoning… | 交给模型自己；pix-optimizer 的 caveman 管输出形状（[§3.5](配置.md)） |
| Read files: no full reads by default… | 交给模型自己；常驻工具只留 `read edit write bash`（[§3.1](配置.md)） |
| Search: 优先 fd/rg | `pi-reflag` 在 `tool_call` 上把 `find`/`grep` 改写成 `fd`/`rg`（[§3.7](配置.md)），比求模型有效 |

- **唯一例外：项目级 `<cwd>/AGENTS.md`**。本仓库根目录那份只写**一条**规则（别写项目级 `.pi/settings.json`，见 [§3.2](配置.md)），只在该项目的会话里进前缀，可按目录拷到别的项目（`cp <仓库>/AGENTS.md <项目>/AGENTS.md`）。用户级 `~/.pi/agent/AGENTS.md` **仍是 0B**，不受影响。
- **canonical 是本仓库 `config/agent/AGENTS.md`，内容 0B**：`node install-project-config.mjs` 会把它拷进 `~/.pi/agent/AGENTS.md`，`--check` 比对 0B ↔ 0B。想重新加规则就写这个文件，别手改盘上那份。
- 它进的是**每轮 system 前缀**，所以**空文件本身就是收益**：system 少一段 = 每轮省 token，且少一个会漂的前缀源。
- 与扩展注入的规则是叠加关系、互不覆盖：现在 system 里只剩 pix-optimizer 的 caveman/ponytail 档位规则（[§3.5](配置.md)）。
